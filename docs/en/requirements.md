# Requirements

Each requirement is listed with **how the ontology meets it** (classes, properties and mechanisms), **how it is verified** and its **status**. Status values:

- **Met** — the requirement is represented in the ontology and checked automatically (tests, SHACL, SPARQL).
- **Met (inspection)** — the requirement is represented, but checked only by reading the model; no automated test yet.
- **Partial** — part of the requirement is represented; the gap is stated.

Requirement → question → class → test links are summarised in [traceability.md](traceability.md).

## Functional requirements

| ID | Requirement | How it is met | Verification | Status |
|---|---|---|---|---|
| FR-01 | Support any artistic medium. | `Artwork`, `Expression` and `Manifestation` (IFLA LRM levels, ADR-028) are medium-neutral; media differences are represented by selectors (time, region, text, SVG) and by the medium families of `ArtisticDimensionScheme` (narrative, verbal, music, visual, audiovisual, paratext). | Examples cover song, recording, novel and film (`examples/`). | Met (inspection) |
| FR-02 | Select partial content at different granularities. | `Selection` (`selectsFrom` an `Expression`, optionally `locatedInManifestation`) located by `hasSelector` → W3C `oa:Selector` (FragmentSelector `t=`/`xywh=`, TextQuote, TextPosition, Svg); `AnalysisUnit` groups selections; derivation anchors may be any `ArtisticEntity`: artwork, expression, manifestation or selection. | SHACL: `selectsFrom` min 1; examples with selectors; annotator schema requires a selector for selection anchors. | Met |
| FR-03 | Allow competing, even contradictory, interpretations. | Several `InterpretationRecord`s may share one primary selection (no functional constraint, ADR-002); `Challenge` (`challenges` any `Claim`) and `supportsInterpretation` represent disagreement and support. | CQ-02 query (competing readings and challenges of one selection); CQ-09 query (authors and assessors). | Met |
| FR-04 | Retain justification and provenance for interpretations. | `hasJustification` → `Justification` (any `Claim`, ADR-026); `producedByAct` → `InterpretiveAct` for any analytical record, so assessments and challenges have authors too (`hasParticipant` → `Analyst`, an external agent IRI); `citesSource` → `ReferenceSource`. | SHACL: `producedByAct` exactly 1, `hasPrimarySelection` exactly 1, participants must be IRIs. | Met |
| FR-05 | Differentiate fiction/representation from empirical occurrence. | Represented world: `SituationDescription`, `DepictedElement`; empirical world: `EmpiricalSituation`, `EmpiricalEvent`, `EmpiricalCase`; separate packages, no shared class (ADR-003). Links between them exist only as `CorrespondenceClaim`s. | Model inspection. | Met (inspection) |
| FR-06 | Generalize represented situations into reusable patterns. | `generalizesAs` (`SituationDescription` → `SituationPattern`); `hasCondition` → `PatternCondition` with `isRequiredCondition`; patterns are independent of any single work and reused by `aspectConcernsPattern` in derivations. | SHACL: `hasCondition` min 1; CQ-04 and CQ-16 queries. | Met |
| FR-07 | Register real-world references independently of artworks. | `ReferenceSource` is a first-class resource not tied to any interpretation (ADR-004); exchange format `schemas/reference-source.schema.json`. | JSON Schema validation of the example source in tests. | Met |
| FR-08 | Allow one source to support multiple cases and multiple claims. | Many-to-many citation properties without upper bound: `citesSource` (one property for every analytical record since 0.3, ADR-026). | CQ-06 and CQ-07 queries (CQ-07 lists sources cited by records of several kinds); examples reuse sources. | Met |
| FR-09 | Distinguish source, evidence, claim and assessment. | Four distinct classes: `ReferenceSource`; `EvidenceItem` (`derivedFromSource` exactly 1); claims (`EmpiricalClaim`, `CorrespondenceClaim`, `DerivationClaim`); `EvidenceAssessment` (`assessesEvidence` ≥ 1, targeting one specific claim, ADR-005). | SHACL cardinalities; CQ-06 and CQ-17 queries. | Met |
| FR-10 | Register similarity, possibility, divergence and causal hypotheses without conflation. | Similarity is represented by `CorrespondenceClaim`; causal or explanatory hypotheses by `ExplanationHypothesis` (`explainsPattern`), kept apart from correspondence; no causal axioms (NFR-05). **Gap:** no vocabulary yet distinguishes similarity, possibility and divergence within a correspondence claim. | CQ-10 and CQ-12 queries (hypotheses and the evidence judged insufficient for them, via `assessmentOutcome`). | Partial |
| FR-11 | Separate epistemic assessment from axiological evaluation. | `CriteriaAssessment` uses explicit `AssessmentCriterion`s (`usesCriterion` ≥ 1). Since 0.3 criteria are `EpistemicCriterion` or `ValueCriterion` (subkinds of `AssessmentCriterion`); the outcome of an assessment is `assessmentOutcome`. | CQ-11 query (criteria by kind); CQ-08 query (outcomes). | Met |
| FR-12 | Support bilingual terminology and traceability to competency questions. | Every term has `rdfs:label`, `skos:definition` and `rdfs:comment` in `@en` and `@pt-BR` (ADR-024); bilingual documentation; [traceability matrix](traceability.md). | Tests check en/pt-BR coverage of every class, property and concept. | Met |
| FR-13 | Record derivation between artistic entities at artwork, expression, manifestation or selection level, as contestable claims. | `DerivationClaim` with `hasSourceAnchor` and `hasDerivedAnchor` (range the «category» `ArtisticEntity`); the level is chosen per claim (ADR-012); each claim links exactly one source and one derived anchor (ADR-015). | SHACL: anchors exactly 1, anchor kind, distinct anchors; negative test; CQ-13 and CQ-14 queries. | Met |
| FR-14 | Type derivations with a controlled, non-exclusive vocabulary. | `hasDerivationType` (≥ 1) → `DerivationTypeScheme` (40 concepts in five families, each citing its literature); stance represented separately by `hasRegime` → `DerivationRegimeScheme` (ADR-018). | SHACL: type min 1 and class `DerivationType`; annotator schema enums generated from the vocabulary. | Met |
| FR-15 | Describe what each derivation retains, modifies, adds, removes or recontextualizes per artistic dimension, including situation patterns. | `hasTransformation` → `TransformationAspect` with `hasDimension` (56 dimensions) and `hasOperation` (5 operations); optional `aspectSourceSelection`, `aspectDerivedSelection` and `aspectConcernsPattern`. | SHACL: dimension and operation exactly 1; CQ-15 and CQ-16 queries. | Met |
| FR-16 | Record creative acts, agents and roles separately from analysts. | `CreativeAct` (`producesCreation`) with `CreativeContribution` relators (`contributionBy` → `CreativeAgent`, `contributionRole` → `CreativeRole`); `CreativeAgent` and `Analyst` are distinct «roleMixin»s filled by external agent IRIs (ADR-019, ADR-022). | SHACL: agent exactly 1 and IRI, role ≥ 1; CQ-18 query. | Met |
| FR-17 | Record the explanation of each derivation claim; legality and originality are out of scope. | `hasJustification` → `Justification` (multilingual text), `citesSource`, `assessesClaim`, `producedByAct` (the same properties as every `Claim`); no class or property represents legality (ADR-014). | CQ-17 query. | Met |
| FR-18 | Locate selections with W3C Web Annotation selectors and exchange derivation annotations in a validatable format. | `hasSelector` → `oa:Selector` (ADR-021); `schemas/derivation-annotation.schema.json`, generated from the vocabularies (ADR-023), with multilingual texts. | Tests validate the example annotation and reject invalid ones. | Met |
| FR-19 | Provide web links through which works, sources and evidence can be consulted. | `aro:externalLink` (`xsd:anyURI`, usable on any resource: work page, recording, evidence location, case report) and `aro:sourceURL` (domain `ReferenceSource`); both documented as access points, not credibility claims. | Annotator shows them as clickable links; ontology tests check bilingual labels. | Met |
| FR-20 | Allow users to instantiate, browse, save and reload annotations without writing RDF by hand. | Web annotator (`annotator/`): creation by class, relations restricted by domain/range, vocabulary pickers, W3C selectors, external agents, multilingual texts, expandable graph, Turtle save/load, in-browser checks; `scripts/annotator.py` serves it. | Manual test in the browser; files it saves pass `scripts/validate.py`. | Met (inspection) |

## Non-functional requirements

| ID | Requirement | How it is met | Verification | Status |
|---|---|---|---|---|
| NFR-01 | Interoperability with RDF/OWL 2. | Ontology published in Turtle, RDF/XML and JSON-LD; external vocabularies reused by IRI (SKOS, W3C Web Annotation, Dublin Core). | Tests parse the three serializations and compare triple counts. | Met |
| NFR-02 | Traceable identifiers. | Stable English IRIs in `https://w3id.org/aro/ontology#`; `identifier` property for local record IDs. **Gap:** the w3id redirect is not registered yet. | Inspection. | Partial |
| NFR-03 | Provenance and citations. | `ReferenceSource` with `sourceURL`, `issuedDate`, `retrievedAt`; `dcterms:source` on every vocabulary concept; acts and agents for interpretations and derivations. **Gap:** PROV-O is linked only through `rdfs:seeAlso`, without a formal provenance model. | Inspection. | Partial |
| NFR-04 | Explicit versioning. | `owl:versionInfo`, `owl:versionIRI` and `owl:priorVersion` generated from the catalog; current version in `ontology/src/`, immutable frozen versions in [`releases/`](../../releases/README.md) (`python scripts/build.py --release`); [CHANGELOG](../../CHANGELOG.md); `CITATION.cff`. | Tests check every release (complete, parses in three formats, declares its own version) and the version IRI. | Met |
| NFR-05 | No unsupported inference of causation. | Causal content is represented only as `ExplanationHypothesis` claims; no causal or transitive axioms are declared; correspondence represents similarity, not causation. | Inspection of axioms. | Met (inspection) |
| NFR-06 | English identifiers with complete EN and PT-BR labels, definitions and comments inside the ontology, and multilingual (BCP 47) content values. | Language policy ADR-024; `textValue` and `derivationExtent` are `rdf:langString`; annotator texts accept a map of language tag → text. | Tests check en/pt-BR coverage; SHACL rejects untagged text; schema rejects invalid tags. | Met |
| NFR-07 | Machine-validatable exchange formats. | JSON Schemas (`schemas/`) and SHACL shapes (`validation/aro-shapes.ttl`); `scripts/validate.py` validates any user data. | Tests run JSON Schema and SHACL validation, including negative cases. | Met |
| NFR-08 | Modular, incremental SABiOx cycle. | Six packages (`artwork`, `interpretation`, `representation`, `pattern`, `evidence`, `derivation`); two documented cycles ([SABiOx plan](sabiox-plan.md), [compilation](sabiox-compilation.md)). | Inspection. | Met (inspection) |
| NFR-09 | Accessible diagrams and readable documentation. | SVG diagrams per package and overview; bilingual documentation; README/LEIA-ME as user guides. **Gap:** no formal accessibility review of the diagrams. | Inspection. | Partial |
| NFR-10 | A single machine-readable catalog from which all operational artifacts are generated and checked. | `model/conceptual-model.json` + `scripts/build.py` generate OWL, SHACL, schemas, reference docs, diagrams and the README class sections (ADR-017). | `build.py --check` runs in the tests. | Met |
