# Design decision register

| ID | Decision | Consequence | Status |
|---|---|---|---|
| ADR-001 | An anchored interpretation is an InterpretationRecord, not a Selection (v0.1 called this "derivation"; the term is now reserved for ADR-011) | Maintain explicit source anchor | Adopted (renamed in v0.2) |
| ADR-002 | Interpretations may conflict | No functional meaning per selection | Adopted |
| ADR-003 | Represented and empirical realms are distinct | Separate SituationDescription and EmpiricalSituation | Adopted |
| ADR-004 | A source is reusable and independent | Many-to-many citation paths; reference can support or challenge different claims | Adopted |
| ADR-005 | Evidence supports a specific assessment, not automatic truth | Explicit EvidenceAssessment | Adopted |
| ADR-006 | Correspondence is an information claim, not a UFO relator | Evaluate before assigning epistemic status | Adopted |
| ADR-007 | OWL is an approximation of reference semantics | SHACL and process rules complement OWL | Adopted |
| ADR-008 | No full UFO-C OWL import | Conceptual grounding documented | Adopted |
| ADR-009 | Native OntoUML exchange file, validated by tools | `model/ontouml/aro.ontouml.json` generated from the catalog, valid against the official OntoUML JSON Schema 1.0.2 and well formed (`scripts/verify_ontouml.py`, rules cross-checked with the official ontouml-js 1.0.0: 0 errors) | Adopted |
| ADR-010 | Identity of abstract propositions vs authored records | Resolved by ADR-026: a claim is an authored record; the same content asserted by two agents or acts gives two claims | Closed (v0.3) |
| ADR-011 | Derivation between works is a contestable DerivationClaim, not a fact-asserting property | Claims can be cited, assessed with evidence and contradicted; prov:wasDerivedFrom, schema:isBasedOn and Wikidata P144 are linked via rdfs:seeAlso only | Adopted |
| ADR-012 | No ontological commitment on whether a cover/translation is a new artwork or a new expression | Each claim states its level through its anchors, any ArtisticEntity: Artwork, Expression, Manifestation or Selection (IFLA LRM levels since v0.3, ADR-028) | Adopted (revised in v0.3) |
| ADR-013 | Each hop of a derivation chain is represented as a separate claim; no transitivity axiom (no owl:TransitiveProperty); chains are retrieved by query | Each hop keeps its own evidence and status (CQ-14) | Adopted |
| ADR-014 | Legality, authorization and originality of derivations are outside the scope of the ontology; derivations are represented with the explanations agents give for them | No authorization vocabulary; derivative works are creations in their own right; Genette's "plagiat" is named UnacknowledgedBorrowing | Adopted (revised in v0.2) |
| ADR-015 | One claim links exactly one source and one derived anchor | Mashups and multi-source works use several claims | Adopted |
| ADR-016 | Derivation types, dimensions, operations, roles and statuses are SKOS concepts typed by high-order classes | Vocabularies extensible without schema change; the vocabulary classes are OntoUML «type»s | Adopted |
| ADR-017 | model/conceptual-model.json is the single source of truth; scripts/build.py generates OWL, SHACL, schemas, reference docs and diagrams | Tests fail if generated artifacts drift from the catalog | Adopted |
| ADR-018 | Derivation stance (homage, parody's critique, play) is a separate DerivationRegime axis, not a type | Types describe mechanism; regimes describe stance (after Genette) | Adopted |
| ADR-019 | CreativeAgent is a «roleMixin»; agents are identified by external IRIs | Any external agent IRI (PROV-O, FOAF, schema.org, Wikidata) is accepted; SHACL requires only an IRI; since v0.3 the role pattern is completed by ADR-029 | Adopted (revised in v0.3) |
| ADR-020 | Artistic dimensions form a SKOS hierarchy by medium family | Annotation tools can offer per-medium lists; use the most specific concept | Adopted |
| ADR-021 | Selections are located with W3C Web Annotation selectors (oa:Selector) via hasSelector; selectorExpression is only a shortcut | Interoperable with annotation tools (media fragments, text quote/position, SVG) | Adopted |
| ADR-022 | Analyst is a «roleMixin» like CreativeAgent | Analysts are external agent IRIs; SHACL requires only an IRI; roles PersonAnalyst and CollectiveAnalyst since v0.3 (ADR-029) | Adopted (revised in v0.3) |
| ADR-023 | The annotator exchange schema (schemas/derivation-annotation.schema.json) is generated from the SKOS vocabularies | Annotation tools cannot drift from the ontology vocabulary | Adopted |
| ADR-024 | Ontology language policy: all IRIs and terms in English; every class, property, concept, scheme, comment, SHACL message and ontology metadata carries en and pt-BR literals; recorded content (textValue, derivationExtent, annotator texts) accepts any BCP 47 language | rdf:langString enforced by SHACL; tests check en/pt-BR coverage of every term | Adopted |
| ADR-025 | Repository layout with current and frozen versions (as in OntoMI): `ontology/src/` holds the generated development ontology and one module per package; `releases/v<version>/` holds immutable snapshots with release notes; every version has `owl:versionIRI` and links to the previous one with `owl:priorVersion` | Citable, comparable versions; `build.py --release` refuses to overwrite a release | Adopted |
| ADR-026 | Claims share one abstraction: `Claim` («subkind» of `AnalyticalRecord`) generalizes InterpretationRecord, DerivationClaim, CorrespondenceClaim, EmpiricalClaim, ExplanationHypothesis and Challenge | One property per role instead of one per kind of claim: `producedByAct`, `hasJustification`, `citesSource` (any record), `assessesClaim`, `challenges`; replaces claimProducedByAct, derivationJustifiedBy, referencesSource, caseHasReference, derivationReferencesSource, supportsClaim, assessesCorrespondence, assessesInterpretation, assessesDerivation; queries such as "claims without grounds" (CQ-19) work for every claim | Adopted (v0.3) |
| ADR-027 | UFO top level: analytical records are one «kind» (`AnalyticalRecord`) with «subkind»s; range unions become «category»s (`ArtisticEntity`, `Agent`); ultimate sortals are pairwise disjoint and abstract classes are disjoint unions of their subkinds | From 22 «kind»s to 7; `owl:AllDisjointClasses` and `owl:disjointUnionOf` make the identity commitments checkable by an OWL reasoner (tests run OWL RL on the examples) | Adopted (v0.3) |
| ADR-028 | Artistic entities follow IFLA LRM: Artwork (work), Expression (realization with its own content), Manifestation (publication or carrier, optional), Selection (portion of an expression) | The 0.2 `Manifestation` becomes `Expression`; `Manifestation` now means the LRM carrier level; `locatedInManifestation` when a selector depends on an edition; LRMoo classes linked by `rdfs:seeAlso` | Adopted (v0.3) |
| ADR-029 | Agents follow the OntoUML role pattern: «category» Agent over «kind» Person and «collective» Collective; the «roleMixin»s Analyst and CreativeAgent are specialized by the «role»s PersonAnalyst, CollectiveAnalyst, PersonCreator, CollectiveCreator, each defined in OWL as the intersection of its kind and its roleMixin | Agents remain external IRIs; typing them `aro:Person` or `aro:Collective` lets a reasoner classify their roles; ARO still records no personal data | Adopted (v0.3) |
| ADR-030 | Relators mediate at least two entities; acts and empirical events and situations have time | `contributionTo` (CreativeContribution → ArtisticEntity, «mediation», min 1); `startDate`/`endDate` accept a year, year-month, date or date-time (SHACL `sh:or` of XSD date types), so precedence questions can be asked (CQ-21) | Adopted (v0.3) |
| ADR-031 | Alignments with the vocabularies ARO overlaps are declared as `rdfs:seeAlso`, never as equivalences: W3C Web Annotation (InterpretationRecord ~ oa:Annotation, hasPrimarySelection ~ oa:hasTarget), PROV-O (acts ~ prov:Activity, producedByAct ~ prov:wasGeneratedBy, hasParticipant ~ prov:wasAssociatedWith), LRMoo (F1/F2/F3, R3/R4, F28), schema.org (Claim, ClaimReview, CreativeWork), FOAF, Dublin Core | Interoperability without importing those ontologies or their commitments; data stays valid ARO | Adopted (v0.3) |
| ADR-032 | Associations between information objects that are not founded on a relator, parthood or participation keep no OntoUML relation stereotype | The OntoUML verifier reports them as warnings, not errors; no commitment ARO does not make (e.g. «material» without a relator) is forced | Adopted (v0.3) |
| ADR-033 | Every analytical record has an author through its act; assessments record an outcome and criteria are epistemic or value criteria | `producedByAct` has domain `AnalyticalRecord`; `assessmentOutcome` ∈ {supports, partiallySupports, challenges, inconclusive, irrelevant} (SHACL `sh:in`); `EpistemicCriterion` and `ValueCriterion` specialize `AssessmentCriterion` (closes the FR-11 gap); all CQs have executable queries | Adopted (v0.3) |
